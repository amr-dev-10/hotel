# Frontend Cloud Run Deployment

This guide deploys the Arcadia dashboard frontend to Google Cloud Run.

The frontend is a Next.js app in:

```text
apps/dashboard
```

Staging target:

```text
Project: arcadia-hotel-staging
Region: asia-south2
Cloud Run service: arcadia-dashboard-staging
Image name: dashboard-web
Branch: staging
GitHub environment: staging
```

## Deployment Model

The dashboard runs as a Next.js standalone Node server in Cloud Run.

Browser traffic:

```text
User
-> arcadia-dashboard-staging
-> Next.js dashboard
```

API traffic:

```text
Dashboard /api/v1/*
-> Next.js rewrite
-> arcadia-backend-staging /api/v1/*
```

Websocket traffic:

```text
Dashboard browser
-> wss://arcadia-backend-staging...
```

No new database, Redis, VPC connector, Cloud SQL instance, or Secret Manager application secret is needed for the frontend.

## Files

| File | Purpose |
| --- | --- |
| `Dockerfile.frontend` | Builds the Next.js standalone dashboard image. |
| `.dockerignore` | Keeps local dependencies, build output, and secrets out of Docker context. |
| `.github/workflows/deploy-frontend.yml` | Builds and deploys the dashboard to Cloud Run. |
| `infra/staging/configure-frontend.sh` | Creates the frontend runtime service account and writes GitHub variables. |
| `apps/dashboard/next.config.ts` | Enables Next standalone output and backend API rewrites. |

## One-Time Staging Setup

Run after the backend Cloud Run service is already deployed:

```bash
cd ~/hotel
git fetch origin
git checkout staging
git pull origin staging
bash infra/staging/configure-frontend.sh
```

The script creates:

```text
arcadia-dashboard-runner-staging@arcadia-hotel-staging.iam.gserviceaccount.com
```

It also writes:

```text
frontend-github-variables.txt
```

Copy every line from that file into:

```text
GitHub -> Settings -> Environments -> staging -> Environment variables
```

## Required GitHub Environment Variables

Generated by `infra/staging/configure-frontend.sh`:

```text
GCP_PROJECT_ID=arcadia-hotel-staging
GCP_REGION=asia-south2
ARTIFACT_REPOSITORY=arcadia-repo
GCP_WORKLOAD_IDENTITY_PROVIDER=...
GCP_DEPLOY_SERVICE_ACCOUNT=arcadia-github-deploy-staging@arcadia-hotel-staging.iam.gserviceaccount.com
FRONTEND_CLOUD_RUN_SERVICE=arcadia-dashboard-staging
FRONTEND_IMAGE_NAME=dashboard-web
FRONTEND_CLOUD_RUN_RUNTIME_SERVICE_ACCOUNT=arcadia-dashboard-runner-staging@arcadia-hotel-staging.iam.gserviceaccount.com
API_PROXY_TARGET=https://arcadia-backend-staging-....a.run.app
NEXT_PUBLIC_API_BASE_URL=/api/v1
NEXT_PUBLIC_WS_BASE_URL=wss://arcadia-backend-staging-....a.run.app
FRONTEND_MEMORY=1Gi
FRONTEND_CPU=1
FRONTEND_MIN_INSTANCES=0
FRONTEND_MAX_INSTANCES=10
```

These are not application secrets.

## Deploy Staging

Option A, from GitHub UI:

```text
Actions -> Frontend CI/CD -> Run workflow
Branch: staging
target: staging
```

Option B, by pushing frontend changes:

```bash
git checkout staging
git push origin staging
```

The workflow:

1. Authenticates to Google Cloud with Workload Identity Federation.
2. Builds the Docker image from `Dockerfile.frontend`.
3. Pushes the image to Artifact Registry.
4. Deploys `arcadia-dashboard-staging` to Cloud Run.
5. Smoke-tests `/platform/login`.

You do not need to run a shell command to start the frontend after deployment. Cloud Run starts the container automatically.

## Verify Staging

In Cloud Shell:

```bash
FRONTEND_URL="$(gcloud run services describe arcadia-dashboard-staging \
  --project=arcadia-hotel-staging \
  --region=asia-south2 \
  --format='value(status.url)')"

echo "$FRONTEND_URL"
curl -I "$FRONTEND_URL/platform/login"
```

Open:

```text
$FRONTEND_URL/platform/login
```

Then log in with the platform admin credentials.

## Production Pattern

Production should mirror staging:

```text
Branch: main
GitHub environment: production
Cloud Run service: arcadia-dashboard
Image name: dashboard-web
Backend target: production backend URL
```

Production GitHub variables should use production values:

```text
FRONTEND_CLOUD_RUN_SERVICE=arcadia-dashboard
API_PROXY_TARGET=https://PRODUCTION_BACKEND_URL
NEXT_PUBLIC_WS_BASE_URL=wss://PRODUCTION_BACKEND_URL
```

Before public production use, update backend `CORS_ORIGINS` to the production frontend domain instead of `*`.
